# 杭电羽毛球接口速约助手

Windows 桌面版位于 `desktop/out`。解压 Windows x64 ZIP，双击 **杭电羽毛球助手.exe**。桌面程序自带前端和预约引擎，运行时无需安装 Python 或 Node.js。项目内的 **启动助手.cmd** 也会打开已打包的 EXE。

桌面版的配置和恢复记录位于 `%LOCALAPPDATA%\HDU Badminton Assistant`，同一用户下的不同解压目录共用。桌面界面通过本地进程管道读取配置和任务状态，预约令牌仅用于引擎。以下命令行章节用于开发和诊断。

## 使用

1. 保持钉钉登录，并至少打开过一次工作台中的“场馆速约”。程序会自动定位本机钉钉的场馆登录存储。
2. 双击桌面 EXE，助手按北京时间选中后天，今天 20:00 放号。例如 11 月 22 日打开时，打球日期为 11 月 24 日。当晚窗口结束后仍显示这一轮，空闲时跨午夜或唤醒会自动更新。手动改期仅在本次打开期间生效。
3. 点击「检查登录」确认场馆登录，再用「只读演练」检查候选时段和放号时间。
4. 点击“启动定时抢约”，建议提前至少 3 分钟启动。助手先完成会话检查，放号前 1 分钟预热，整点直接发送预约请求。程序可以在后台运行，电脑须保持联网且不休眠。
5. 成功后助手停止，并显示订单。**立即在钉钉完成同行邀请**；当前页面提示 10 分钟内至少邀请 1 人，否则预约会自动取消。助手不自动发送邀请。

启动图形界面不会自动开始预约。开发测试没有创建真实订单；真实创建须由你配置日期并点击“启动定时抢约”。

## 默认选择规则

- 只选 **10:00 或更晚开始**、连续 **60～120 分钟**的场地。
- 接受连续 100 分钟等非整小时时段；不足 60 分钟的格子不单独预约。
- **时长从长到短**，相同时长按场地 **6、7、5、8、1、2、3、4、9、10、11、12** 排序；同场地相同时长选更早开始的。
- 因此其他场地的两小时会排在 6 / 7 号场的一小时前面。
- 默认仅免费场地，每个订单连续、同一个场地，最多使用每日 2 个后台时段；后台时段不一定等于一小时。该日已有本场馆预约时停止，不追加、不取消换场。
- 场地顺序可在界面修改；没有列入顺序的场地不参与候选。日期、放号偏移、开始时间和时长范围均可配置。

“覆盖放号时间”留空时采用上述日期规则。如要补抢已有日期，可以填写一个即将到来的北京时间；仍执行同样的时段、账户及结果保护。

## 接口与速度

已核对当前 H5 程序：场馆和余量查询分别使用 `post_venue_info`、`post_site_situation`，提交必须依次执行 `creat_book_info` 和 `creat_order`。前者可能产生临时占用，**演练绝不调用它**。

候选使用后台真实时间边界、实际场地 ID 和价格。开放状态按客户端的 `rest_list XOR oci_time_list` 计算，占用状态来自 `book_time_list`。默认提前 2 天，若场馆返回的可见天数与配置不一致，界面会提示。

首页「场馆公告」展示场馆速约个人预约页的原文。启动后后台刷新，此后每 10 分钟更新，支持手动刷新。放号前 60 秒至抢场窗口结束会延后公告请求。断网时显示上次成功同步时间，场馆撤下公告后显示「暂无公告」。

助手使用独立的读写长连接。放号前 60 秒每秒读取一次余量，最后 5 秒默认每 100 毫秒读取一次；整点的写入不等待正在进行的余量请求。明确尚未放号时，前 3 秒每 100 毫秒尝试，随后每 500 毫秒，至多到整点后 30 秒停止新的预提交。已经确认占用的那次请求可继续完成创建和结果核对；为令牌续期保留有限恢复时间，默认从确认占用起最多 42 秒，该时间是本地恢复上限而非服务端占位有效期。429 限流由读写连接共同遵守 `Retry-After`，不靠并发写入冲击接口。

服务器时间经多次测量后采用最低往返样本校准；调度使用 `perf_counter` 单调高精度时钟。Windows 执行进程临时请求 1 ms 等待精度，最后 2 ms 短暂自旋，退出后恢复等待精度。不会修改 Windows 系统时间。

本机 2026-11-19 的验证结果：

- 真实只读查询能生成候选，校准时最佳往返约 6.8 ms；本机时钟当时比服务器快约 4.6 秒，已由调度校准抵消。
- 最后一轮 100 次离线测量，预提交函数入口到派发请求的本地开销中位数约 2.1 ms，95 分位约 3.1 ms；包含原子运行记录写入及 `fsync`，不包含网络和服务器处理时间。
- 实际重新进入钉钉免登流程后，约 8 秒取得新令牌，账户查询通过。
- 71 项离线测试通过；另已验证真实执行进程进入等待后能由管理器停止，未派发预约。

以上是该次环境测量，不是整点负载下的预约耗时或成功保证。真实放号的两步写入尚未做端到端预约验收。

## 令牌过期与重启

正式任务在启动时、长时间等待期间每 15 分钟、放号前 10 分钟、2 分钟和 1 分钟查询「我的预约」。已知令牌有效期到了会安排一次只读检查。界面显示预约接口最近验证成功的时间。

默认开启「放号前 3 分钟重启钉钉并验证登录」。助手先退出钉钉客户端，再打开场馆速约并核验原账号。钉钉窗口和通话会随客户端退出。「检查登录」旁的「重启钉钉」可手动执行同一流程。等待中的定时任务会继续，放号前最后 1 分钟与提交期间暂停该按钮。

钉钉窗口显示「游客」时，可点击「打开场馆登录」重新进入钉钉免登页，原任务会继续等待。同账号更新会话后，助手会在只读检查时重新核验。进入放号前 1 分钟后，手动打开入口会暂时不可用。

场馆明确拒绝登录后，助手先尝试使用钉钉当前账号的新会话。早期恢复登录会尝试打开一次场馆页。每轮仍可在放号前 3 分钟执行一次客户端重启。恢复后核对账号、记录和订单，再继续原任务。

免登失败后，助手保留原任务并等待钉钉登录。完成本人确认并打开场馆速约后，助手会检测新会话，也可点「已登录，重新验证」。账号不一致时保持暂停。网络异常和限流按接口退避时间重试。等待期间可停止，放号窗口结束后停止发起新的预约。

本机读取器仅提取 `https://sportmeta.hdu.edu.cn` 下的场馆令牌与提交所需字段。只读解析 LevelDB 的当前 manifest、有效表和日志，遵守删除记录，不从旧缓存里翻找已经删除的令牌。令牌只保存在进程内存中，不写配置、日志、命令行或运行记录。账户变化会阻止继续写入。

诊断日志 `login-events.jsonl` 位于桌面设置目录，记录时间、阶段、错误类别和结果。账号信息、令牌、订单详情及服务端原文均不写入该日志。

## 冲突、停止与不确定结果

- 部分冲突时，只保留剩下的连续 60～120 分钟。存在更优完整候选且临时占用释放得到明确确认，才切换；否则优先完成当前合格时段。
- 每一步写入之前持久化运行记录。响应丢失、异常退出或无法确认临时占用释放时，先查本人订单，绝不直接重发。
- 状态 `UNKNOWN` 表示该日期的结果仍需核对。切回该日会先核对原账号订单；其他日期使用各自的恢复记录。请保留旧记录，以便核查。
- 明确的预提交鉴权拒绝可在续期后重新预提交；预提交已确认成功、创建订单被明确鉴权拒绝时，续期后仅恢复原来的创建阶段。
- 点击“停止”或关闭界面会通知执行进程退出。已发出的请求不能撤回，结果不明时记录会保留。关闭管理进程后执行进程也会停止。

## 命令行与配置

### 重新构建 Windows 免安装包

构建机器需具备 64 位 Python、Node.js 22.12 或更新版本和 npm。下面的命令使用项目已有的 `.venv`；也可向构建脚本传入 `-Python` 指定解释器。

```powershell
.\.venv\Scripts\python.exe -m pip install pyinstaller==6.22.3 Pillow==11.3.0
Push-Location .\desktop
npm.cmd ci
Pop-Location
& .\desktop\build.ps1
```

解压版目录在 `desktop/out/杭电羽毛球助手-win32-x64`，ZIP 在 `desktop/out/make/zip/win32/x64`。打包仅引入桌面界面、后台和运行组件。新版配置或恢复记录已存在时，迁移保留该文件。手动迁移前先关闭旧助手，然后从项目根目录执行：

```powershell
& '.\desktop\.bundle\venue-engine\venue-engine.exe' --migrate (Get-Location).Path
```

### 旧命令行入口

桌面版和已迁移机器上的旧命令行默认共用用户目录。使用自定义配置时可以传入 `--config`，用 `--state-dir` 指定隔离的运行状态目录。项目里的 `api-profile.example.json` 列出所有配置选项。

```powershell
# 联网只读演练，绝不预提交、创建或取消
.\.venv\Scripts\python.exe venue_assistant.py --check

# 只刷新钉钉令牌并查询账户，不预约
.\.venv\Scripts\python.exe venue_assistant.py --refresh-session

# 按已保存配置启动真实定时任务
.\.venv\Scripts\python.exe venue_assistant.py --run --config api-profile.json

# 完整离线测试；不连接真实场馆
.\.venv\Scripts\python.exe -m unittest -v test_venue_api test_venue_session test_venue_core

# 离线测量本地派发开销
.\.venv\Scripts\python.exe bench_venue_api.py
```

`storage_path` 留空时自动定位最新版本钉钉的默认 Local Storage。如钉钉改变存储布局或存在特殊配置，可填写对应的 `Local Storage\leveldb` 目录；不能指向其他人的会话。

## 文件与依据

运行快照存为 `run-api-config.json`，新恢复记录按打球日期保存在 `journals/YYYY-MM-DD.json`。旧版 `run-api-journal.json` 会按原日期读取。空闲时可用「清空显示」清除本轮面板；新任务自动清屏，普通结果保留 60 秒。公告和防重复记录独立保存。

旧视觉实现保留为 `legacy_visual_assistant.py`，其核心与旧测试仍在原文件中，启动助手已不再使用视觉实现。`requirements.txt` 中的 Pillow 仅用于旧实现及其回归测试。

接口依据为调研时的[程序首页](https://sportmeta.hdu.edu.cn/book/dingtalk/)、[预约代码](https://sportmeta.hdu.edu.cn/book/dingtalk/static/js/pages-book-soloBook.219e7e55.js)和[登录代码](https://sportmeta.hdu.edu.cn/book/dingtalk/static/js/pages-boot-boot.86488123.js)。[学校试运行通知](https://pe.hdu.edu.cn/2025/1103/c12309a287132/page.htm)包含每日时段及同行邀请规则，实际限制以服务端和当前页面为准。

LevelDB 读取格式参考 Google 的[日志格式](https://github.com/google/leveldb/blob/main/doc/log_format.md)和[表格式](https://github.com/google/leveldb/blob/main/doc/table_format.md)。应用更新导致接口结构变化时，助手会停止写入并提示不兼容。
